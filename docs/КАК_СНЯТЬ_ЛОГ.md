# Как снять лог прогона в AutoCAD

Порядок прогона — что, в каком файле и когда запускать — в
`docs/ИНСТРУКЦИЯ_ПРОГОН.md`. Здесь только про съём и отправку текста.

Логи программа не пишет намеренно (требование ТЗ): всё идёт в командную
строку. Поэтому лог снимается из текстового окна AutoCAD — **F2**.

## Порядок

1. **Сохраните чертёж под другим именем** и работайте в копии. Прогон
   меняет чертёж: заменяет экземпляры и стирает сиротские `*U`.
2. Скопируйте новую версию блока из файла-источника: **Ctrl+C** с базовой
   точкой, затем **Ctrl+C** на сам блок (`Комплект КП50 v1.5`), чтобы в
   буфере оказалось именно новое определение.
3. В AutoCAD: `APPLOAD` → `Integration.lsp`. В командной строке появится
   баннер `Integration.lsp, сборка 47. Команды: ...` — убедитесь, что
   сборка 47.
4. Снимок таблицы блоков **до** прогона:
   ```
   (setq KG-TRACE t)
   INTCOUNT
   ```
5. Прогон:
   ```
   INTEGRATE
   ```
   Очистка встроена в конец `INTEGRATE` (`KG-AUTOCLEAN = t`), отдельный
   запуск не нужен. Если хочется разделить — `(setq KG-AUTOCLEAN nil)`
   перед `INTEGRATE`, потом `INTCLEANUP` отдельно.
6. Снимок **после**:
   ```
   INTCOUNT
   (setq KG-TRACE nil)
   ```
   Последний шаг обязателен: с включённым `KG-TRACE` на 100 блоках лог
   будет огромным.

Альтернатива пунктам 3–6 — скрипт `testbed/test-run.scr` (команда
`SCRIPT`); путь в первой строке поправьте под своё расположение файла.

## Как отдать лог

1. **F2** — откроется текстовое окно AutoCAD.
2. **Ctrl+A**, **Ctrl+C**.
3. Вставьте в текстовый файл.

### Если в чат не вставляется

Полный лог с `KG-TRACE t` на чертеже с десятками определений — это сотни
килобайт текста, в поле ввода он не помещается. **Лог целиком присылать не
нужно** — хватит коротких команд, их вывод копируется вручную:

| Команда | Сколько строк | Когда |
|---|---|---|
| `INTERR` | 5–10 + выжимка | **команда упала** — ошибка, шаг падения, состояние чертежа |
| `INTBRIEF` | 10–15 | очистка отработала не так, как ожидалось |
| `INTCOUNT` | по определению | нужно видеть, кто кого держит |

1. Если команда упала — первым делом:
   ```
   INTERR
   ```
   Она печатает текст ошибки и шаг, на котором всё оборвалось. Раньше это
   было невозможно: `KG-ErrorRestore` обнулял «последний шаг», и к моменту
   письма улика исчезала. Теперь ошибка запоминается и переживает
   следующие команды.
2. Дальше — выжимка состояния:
   ```
   INTBRIEF
   ```
   Сколько определений всего, сколько с суффиксом `~до`, сколько сиротских
   `*U`, что мешает их стереть, разрешено ли стирание.
3. Если нужно больше — блок `=== Результат ===` и строки
   `Вариант "...": ожидалось/стало` из лога (их можно найти в F2 поиском).
4. Вложение файла — тоже вариант: сохраните лог из F2 как `log.txt` и
   добавьте к сообщению как файл, а не как текст.

Полный лог с `KG-TRACE` нужен, лишь если по `INTERR` + `INTBRIEF` причину
найти не удалось. Тогда отрежьте начало (загрузку и старые прогоны) и
пришлите от строки `=== Интеграция новой итерации семейства` до конца.

## Что присылать обязательно

* Весь блок `=== Результат ===` — построчно, со всеми счётчиками.
* Строки `Вариант "...": ожидалось N, стало M` — все.
* Весь вывод очистки: `Своих определений без ссылок`, `Сиротских анонимных
  представлений (*U)`, `Стёрто сиротских *U: X, не удалось: Y`, и **все**
  строки вида `[шаг] стирание "*U…": причина` — именно по ним видно,
  почему определение не стерлось.
* Вывод `INTCOUNT` до и после (можно только группы и первые 20 строк
  каждой, если определений сотни).
* Если команда упала — строки `ОШИБКА: ...` и `Последний шаг: ...`
  целиком.

## На что смотреть самому

| Строка отчёта | Что должно быть |
|---|---|
| `Заменено экземпляров` | равно числу старых экземпляров |
| `Потерь экземпляров` | 0 |
| `Ошибок` | 0 |
| `Вариант "...": ожидалось/стало` | везде `[OK]` |
| `Вложенных блоков не найдено в новой версии` | 0 (в сборке 40 это чинилось) |
| `Восстановлено состояний видимости` | равно `Прочитано состояний вложенных блоков` |
| `из них у представлений (*U)` + `из определения` | в сумме равно `Прочитано состояний` |
| `Стёрто сиротских *U` | > 0, если сироты были (в сборке 41 чинилось) |
| `не удалось` | 0; если не 0 — причины в строках `[шаг] стирание ...` |

## Про 100 блоков

Проверять стоит на копии рабочего чертежа, а не на стенде `INTTESTBED`:
он создаёт статические блоки без динамики и без вложенных определений,
то есть ровно те ветки, которые чинились, на нём не исполняются.

Что добавляет прогон на 100 экземплярах: время (обход содержимого
определений идёт на каждый экземпляр), число сиротских `*U` (в прошлом
прогоне их было 43 на 3 экземпляра) и нагрузку на `PURGE`. Если команда
начнёт идти долго — это нормально, но пришлите, сколько заняло.

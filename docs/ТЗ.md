## 1. Предмет

В текущий чертёж (реципиент) интегрируется новая итерация семейства
динамических блоков, пришедшая **из буфера обмена**. Все существующие
вхождения старых итераций того же семейства заменяются на новую, с
созданием недостающих вариантов и сохранением исходной видимости
вложенных блоков.

## 2. Источник данных

| Допустим режим B: пользователь вставил мастер-блок руками и указывает его команде | реализовано |

## 3. Модель имён

Основная (производственная) схема: **`БАЗА vВЕРСИЯ [ВАРИАНТ]`**.

* версия — всегда `v` + цифры через точку: `v1.1`, `v1.5`, `v1.21`, `v2.0`;
* мастер-версия — имя без варианта: `Комплект КП50 v1.5`;
* вариант отделяется пробелом и может содержать пробелы и дефисы:
  `Комплект КП50 v1.21 стойка КП45302-1`;
* база может содержать что угодно, в том числе пробелы;
* **буква в конце базы — другое семейство**: `Комплект КП50К` ≠ `Комплект КП50`;
* версии сравниваются по частям, поэтому `v1.21` старше `v1.5`;
* старой считается любая итерация, отличная от новой.

Вторая поддерживаемая схема: **`БАЗА(ИТЕРАЦИЯ)ВАРИАНТ`**
(`ABC1.01(15)Стойка`). Разбирается последняя закрывающая скобка.

| Требование | Статус |
|---|---|
| Ничего не зашито на конкретное семейство: база, итерация и вариант берутся из фактического имени пришедшего блока | реализовано |
| `ABC1.01(15)Стойка` — только пример второй схемы, не образец для констант | реализовано |
| Имена без узнаваемой версии (`Стойка КП50 контур`) семейством не считаются | реализовано |

**Правило нумерации итераций** (уточнение заказчика): номер без нуля на
конце, когда он круглый. `v1.5` = 50, `v1.2` = 20, `v1.21` = 21,
`v1.51` = 51. Одноразрядная часть после точки означает десятки, поэтому
`v1.5` и `v1.50` считаются одной и той же итерацией (50). Внутри программы
итерация — строка, сравнение по нормализованному ключу `KG-IterKey`.

## 11. Команды

Реально определены в сборке 66 (проверено загрузкой файла):
Основная: `RDB` (алиасы: `RepDblock`, `ПОДМЕНАБЛОКА`, `ПДБ`, `INTEGRATE`).
Диагностические и служебные: `RDBCHECK`, `RDBDIAG`, `RDBDUMP`, `RDBDUMPDEF`, `RDBPASTETEST`,

`RDBBRIEF`, `RDBERR` (с сохранением алиасов обратной совместимости `INT*`).

| Основная команда | Алиасы | Назначение |

## 12. Ограничение на состав команд (уточнение заказчика, сб. 61)

**Все действия выполняются одной командой `RDB` (или `INTEGRATE`).** Отдельная команда
обновления одноимённых блоков (`BLOCKUPDATE` и подобные) заказчиком
отвергнута.

## 13. Приёмка

Действующий перечень, по которому фактически проверялось:

1. Новая итерация взята из буфера, без файлов и ручного ввода.
2. Все старые итерации семейства заменены; посторонние семейства не тронуты.
3. Суффиксы вариантов сохранены у всех экземпляров.
4. Количество по вариантам и общее совпало с исходным.
5. Положение, масштабы, поворот, нормаль, слой сохранены; экземпляр не
   переехал между моделью и листом.
6. Вложенные определения обновлены глобально, под своими именами; новые
   добавлены; отсутствующие в новом мастере не удалены.
7. Видимость по экземплярам и по вложенным блокам сохранена; при
   отсутствии состояния — первое доступное плюс предупреждение.
8. Итоговые имена чистые: без `$0$`, `$1$`, `_new`, числовых, `копия`.
9. Технический экземпляр удалён, итоговое количество не изменилось.
10. XREF не обработаны и не повреждены.
11. Временных файлов и файлов журнала нет.
12. Отчёт в командной строке содержит счётчики и называет отказы по шагам.
